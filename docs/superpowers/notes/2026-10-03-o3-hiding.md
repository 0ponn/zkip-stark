# 2026-10-03: O3 settled, the proof is not zero-knowledge

**Question.** Does Aiur's STARK hide the witness (the attribute value and
Merkle path) from whoever holds the proof?

**Answer: no, by the library's own documentation.** The pinned `multi-stark`
(`argumentcomputer/multi-stark@2c01922`, also its upstream HEAD) states in
`src/verifier.rs`:

> This protocol is a succinct argument of knowledge, **not** a zero-knowledge
> proof: traces are committed without blinding, and FRI query responses reveal
> actual low-degree-extension values of the witness. Do not use it when the
> witness must remain hidden from the verifier.

Mechanically: every FRI query opens evaluations of the committed trace columns
at coset points, and the out-of-domain openings at the random point reveal
one linear functional of each column. Each opened value is a known linear
combination of the trace cells. Our secret is tiny (4 attribute bytes plus
the path bytes), so the hundreds of linear equations a proof publishes are
more than enough, in principle, to solve for it when the surrounding cells
are known. Treat the attribute as disclosed to anyone who holds the proof.

**What M1/M5 do guarantee.** The attribute is not in the public claim
(`leakCheck`), so a party that sees only `(threshold, commitment, verified)`
learns nothing beyond the predicate. The proof bytes themselves must be
handled as sensitive.

**Path to actual hiding.** Plonky3 at the pinned revision already ships the
pieces: `fri/src/hiding_pcs.rs` (`HidingFriPcs`, `ZK = true`) and
`uni-stark`/`batch-stark` honor `Pcs::ZK` by doubling the trace with random
rows and randomizing the quotient. `multi-stark` instead uses
`TwoAdicFriPcs` (`ZK = false`) and has its own prover, verifier and lookup
accumulator, so blinding is a change inside `multi-stark`, not here: switch
the `Pcs` alias, adopt the randomized trace and quotient handling, and blind
the lookup argument. Expected cost: roughly 2x trace length, so roughly 2x
prove time and proof size. Upstream has no such work in flight.

**Decision.** Restate the guarantee honestly now (done in this commit:
README, architecture, REMEDIATION). File the blinding work as a
`multi-stark` issue; do not claim zero-knowledge until it lands and is
re-verified here.

## Addendum (same day): M6 shipped blinding

The path above was taken: `0ponn/multi-stark@53131ae` (prover and verifier
generic over `Pcs::ZK`, `GoldilocksBlake3ZkConfig`, a `Sync` hiding MMCS) and
`0ponn/ix@5f7f088` (`AiurConfig` is the ZK config). Cost on this machine:
about 5x prove, 2x verify, 1.8x proof size. Residual: public lookup
accumulators. Handoff: `docs/superpowers/notes/2026-10-03-m6-handoff.md`.
