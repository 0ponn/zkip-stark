# M13: Long-running API server with auth

Status: done locally (2026-10-05). Operator approved ("build it"), with the
thread cap defaulting to 4.

## Why

`Main` served one request per process under socat, so every request rebuilt
the circuit and recalibrated, and anyone who could reach the port could make
the machine prove. The machine also runs production apps.

## Design

- One process, Lean's native async TCP (`Std.Internal.Async.TCP`), one
  connection at a time. The listen backlog is the queue, so at most one proof
  runs at once.
- Binds 127.0.0.1; `--public` binds 0.0.0.0.
- `ZKIP_API_KEY` is required at startup. Generate and batch need
  `Authorization: Bearer <key>` (constant-time compare; 401 otherwise).
  Verify, health and ready stay open, because verifying is cheap and is
  meant for third parties.
- Limits: 16 KB of headers (431), 64 MB of body (413, enough for a verify
  body of about 20 MB), 10 s idle per read and 60 s per request (408), so a
  slow client cannot hold the queue.
- `scripts/serve.sh` defaults `RAYON_NUM_THREADS` to 4 and execs the server.
  Rayon reads it at pool start, so it has to be set before launch.
- The circuit and the single-disclosure shape are built at startup, so the
  first request is not slow.

## Units

1. `Main.lean` rewrite: request reading with limits, routing with auth,
   startup checks.
2. `test_all.sh` sends the key and adds 401 cases (no key, wrong key; verify
   open). `test.yml` runs the server directly (no socat).
3. Docs and launcher script, then the local run and PR.

## Results

- Idle memory is 447 MB. Two consecutive proofs from one process took about
  4.0 s each at 4 threads and lowest priority, and both verified.
- Raw-socket checks: idle client 408 after 10.1 s; half a request then
  silence 408 after 10.0 s; oversized body 413; 20 KB of headers 431 (a first
  version returned 200 when the headers arrived in one chunk; fixed); batch
  without a key 401; garbage request line 400. The server keeps serving after
  each.
- Startup refuses a missing key or one shorter than 16 characters.
- `test_all.sh` passes 10/10 (two new 401 cases). Generate and verify now
  share a process, so `scripts/cross_process_check.sh` proves on one server,
  restarts, and verifies on a fresh one; CI runs it.
- Known limits: one slow client can hold the queue for up to 60 s; the key's
  length is not hidden; chunked bodies are unsupported (400).
